# 來源審查、最終交付驗證與有界修復

流程為 Parse → Normalize → Enrich → Package → Chunk → 來源審查 → 按需修復／重新 Package、Chunk → 修復後審查 → 最終驗證 → 發布版本。審查在 chunk 階段保存進度與恢復紀錄。
Word 原生解析失敗時沿用 Word → PDF → MinerU 備援。原生 Word 的頁碼標為 logical，PDF 解析可標為 physical。Agent v2 先解碼原始內嵌圖片；EMF／WMF 等向量圖則從原 Word 找出相同圖片雜湊的段落，獨立轉成 PDF 再繪製，不把向量資料偽裝成 PNG。表格可將 Word 轉成 PDF，依文字比對最多三頁連續來源；重複工作名稱降低比重，獨特表頭提高辨識力。對應不明確時保留待確認，不把 logical 頁碼當成 PDF 頁碼。

## 預設行為

- 短內容、混合文件非表單部分及結構化輸出未涵蓋的區塊會保留。
- Word 合併儲存格保留 rowspan/colspan；解析快取版本已更新。內容控制項（SDT）內的段落、文字、表格與圖片會依原順序讀取，控制項屬性不當成內文；解開結構只作用於記憶體，不修改原始 Word。
- 文件與最終 chunks 分別做內容覆蓋檢查，不以 source.md 代替交付證據。
- 過長 chunks 依設定 token 估計上限分割，保留重疊與來源 block IDs。
- UI 同時顯示執行狀態與交付品質；舊產物沒有最終驗證資料時顯示尚未驗證。
- 新 run 的 agentic.mode 預設 apply，fast／accurate 都安排來源審查。既有 run 已保存的設定與完成產物不會自動重跑或改寫。

覆蓋檢查使用正規化文字、字元片段與精確數值 token，反映文字保留程度。它不能證明圖像語意、數值與欄位配對或 OCR 本身全都正確；自動排除頁首頁尾、裝飾圖與隱私遮罩會在 coverage.json 記錄原因或政策。

## 審查範圍與驗收

先從原始 PDF／影像或 Word 轉出的 PDF 建立實際頁面清單，再逐頁比對來源圖與真正交付的文件片段、chunks。即使整頁沒有任何解析區塊，也會列入清單。Word 的 logical page 不當成實體頁；文字／表格依來源比對，重複且無法唯一對應的區塊保留未核對。

所有來源頁面與實質區塊都排入審查。時程空格、合併儲存格等原規則只決定先後順序，不決定是否需要審查。相鄰頁影像與邊界區塊提供續表上下文；表格／圖片裁切保留細節。主文沒有空白分段時，依實際行文分成有界片段，避免把整份文件送進單頁請求。

每頁與每個區塊分別記錄 verified（已核對）、needs_review（待確認）、not_reviewed（未核對）。來源清單不完整、頁面對應不明、輸入過大、模型回應無效、預算耗盡，都不能算作通過。頁面缺漏可被攔下；預設由文件工具控制器選擇表格、圖片、文字、漏頁及來源對應的修復方法；停用 recovery_enabled 時才走原有局部修復器，仍須來源證據及候選驗證（見下方文件層級工具控制器）。

預設先完成可負擔的逐頁第一輪審查，再由文件工具控制器處理問題，不讓前幾頁的修復占用後續頁面的基本審查機會。修復與審查共用同一份持久化時間、呼叫及動作預算；總額度不足仍會留下明確未核對頁，不能宣稱完整通過。修復採用後重新產出文件與 chunks，再核對實際交付內容。原圖 hash 或交付內容變更會使相關核對失效。最終驗收直接檢查審查清單、影像 hash、IR 身分及實際交付 hash，不再用原風險規則代替全面核對。

未核對頁面一律保留在分母中。UI 顯示已核對／總頁數、待確認頁數、未核對頁數；舊產物沒有來源審查紀錄時顯示「尚無來源核對紀錄」，不將舊文字覆蓋驗證當成新的來源語意驗證。

## 設定模式與預算

建立 run 時，透過既有 POST /api/runs 的 config_overrides 指定：

```json
{
  "doc_id": "既有文件 ID",
  "profile": "accurate",
  "config_overrides": {
    "agentic": {
      "mode": "shadow",
      "max_actions": 2,
      "max_attempts_per_block": 2,
      "max_model_calls": 6,
      "max_seconds": 240,
      "max_output_tokens": 4096
    }
  }
}
```

建立後仍需透過既有 execute API 執行。

- off：不進行 agent 模型呼叫，來源審查標記未核對，不能自動取得來源驗收通過。
- shadow：審查實際交付並保存修復候選與證據，交付仍使用原 IR；未修正問題仍待確認。
- apply：完整且驗證通過的修正統一用於交付 Markdown、資產與 chunks；原始表格／文字仍保存在 IR 與 dataset.md 作為來源證據。相同階段的舊 package VLM／semantic repair 停用，避免再套一層修復迴圈。

agent 使用現有 vlm 與 review_vlm 設定；不自動建立新端點。預設工具見下方文件工具控制器；停用 recovery_enabled 的舊局部模式允許 inspect_page、reconstruct_table、describe_figure、keep、needs_review，不能執行 shell 或改預算。來源文件中的指令不具有工具權限。

先獨立讀取原圖，再讓決策器比較來源解讀、表格 HTML、Markdown 與區塊 RAG 表示。重建／驗證只將原 OCR 視為未驗證的文字片段，避免沿用錯誤欄位配對。keep 也要有完整來源解讀及另一次驗證，確認兩種原有表示都正確才能保持原文並解除待確認。控制器另比對已驗證事實與其引用的原始儲存格；若來源解讀修正了原欄位內容，即使模型又判定 keep，也採用已通過驗證的修正。

候選必須涵蓋每個資料儲存格；明確表頭與時程軸另行保留並驗證，不必捏造表頭事實。同名工作仍有不同來源 ID。較長的儲存格另查文字片段保留程度：同來源列的事實合計至少保留 80% 的三字片段，允許局部 OCR 更正及同列欄位重新配對，但不能只引用整格就省掉子項／段落。這是漏文防線，不是語意正確率。

驗證的每段觀察明確列出支持哪些 fact indices 與 source cells，可一段支持多項，但所有關係及對應都必須通過並確認完整性。明確宣告並核對的共用表頭可支持各列；資料儲存格仍須逐項核對，不能將一般資料當作共用表頭略過。實體表格保留目標裁切的細部解析度，另附可能的相鄰頁，最多三張影像。檢查不通過的詳細觀察帶入下一次嘗試；仍缺頁、缺欄或達上限時保留原文與待確認。

兩次模型判斷一致仍不能視為人工正確率。保留原始來源、圖片雜湊、逐項核對紀錄；無可靠來源、回傳不合法、驗證未過或預算耗盡時不採用候選。這是有界局部修復，不是整份文件皆經語意驗證。

上述預算限制 agent 增加的逐頁審查、決策、重建、驗證與取證準備；Word 取證轉檔也計入時間上限，單次轉檔至多 120 秒；逾時／取消後的程序與管線清理另保留至多 5 秒，不允許無界等待。既有 parse/enrich 基礎成本另計。新工作預設六次工具動作；呼叫／時間採下方的自適應預算，舊局部模式每區塊最多兩次嘗試。決策輸出至多 768 tokens，重建／驗證至多 4096 tokens（仍受設定上限限制）。被截斷或不合法的回應也記錄已回報 tokens、停止原因及錯誤，錯誤會帶入下一次嘗試；不在控制器外偷偷重試。模型未回報的用量不能推算成精確帳單。

## 狀態、恢復與發布

每個 run 使用：
- execution.json：已提交背景執行的持久化紀錄。
- checkpoint.json：輸入指紋、候選 revision、已完成階段與中間狀態。
- revisions/<id>/：該次候選的 IR、assets、outputs、agentic 證據。
- current：原子切換的目前發布版本。既有 outputs 等路徑保持相容。

背景佇列重啟後只恢復有有效 submission 的工作；取消會移除提交紀錄。沒有提交紀錄的舊 pending/running 維持舊有取消策略。同步 execute 的中斷可再次呼叫 execute 接續，不會自動排入背景佇列。

保存 normalize baseline 與 enrich 後 IR；agent checkpoint 記錄已接受事實、嘗試與用量。中斷的呼叫可能已在模型端完成但尚未記錄回應，不能保證外部請求 exactly-once；預算先記帳以限制重複成本。

發布前核對文件、chunks、IR、來源對應與圖片的 SHA-256。驗證報告完整產生後才切換 current；未達品質要求的完整版本可以發布供人工查看，但 auto_rag_ready=false。讀取 API 固定使用同一個 revision。這套互斥與佇列設計適用目前單程序服務，尚非多機分散式工作排程。

輸出：
- outputs/review_coverage.json：來源清單完整性、逐頁／逐區塊審查狀態、模型觀察、證據與交付 hash、總用量；batch download 的 file_types 可指定 review_coverage。
- agentic/review_state.json：全面審查的持久化預算、恢復狀態與修復紀錄；耗盡後接續仍讀取既有來源頁面清單，不縮小分母，也不重新啟動無預算的 Word 轉檔。
- outputs/coverage.json：區塊對應與排除理由。
- outputs/delivery_status.json：執行、品質與最終驗證狀態。
- outputs/delivery_manifest.json：整組發布檔案雜湊。
- outputs/quality.json 的 delivery 欄位：沿用既有下載入口。
- outputs/agentic_report.json、agentic/state.json：額外成本、動作、接受／保持原文／未解問題與逐項驗證。
- agentic/evidence/：Word 轉檔與原圖副本，納入發布檔案雜湊；恢復前也核對已接受來源是否仍相同。

auto_rag_ready 必須同時滿足來源清單完整、所有來源頁與實質區塊已核對、證據與實際交付 hash 一致、最終交付通過、品質 pass、有 chunks，且沒有上游禁止自動使用的狀態。內容覆蓋通過不會清除已有品質警告。

## 文件層級工具控制器（2026-09-17）

來源審查後，新增 RecoveryController 問題處理循環。模型看到單一問題、來源頁概覽、有限的區塊摘要、剩餘預算與歷次工具結果，自行選擇工具；程式驗證工具名稱、目標範圍與參數後執行。這不是任意 shell 或全文件長上下文代理。

工具及按需載入的策略文件位於 app/pipeline/recovery_skills/*/SKILL.md：

- inspect_layout：唯讀查詢一個實體頁的 MinerU 版面區塊，回傳來源綁定 ID、類型、0..1000 頁面座標及可用時的分數。優先重用本次解析快取；缺少時只解析該頁，並與 reparse_pdf 共用具 hash 的解析快取。統一 middle、pipeline 像素／多邊形、hybrid/VLM 比例座標及 content_list 格式；不把 Word logical page 或未知單位當實體座標。原生 Word 已有可靠頁面位置的圖片一併列入，provider=word_native 與 MinerU 偵測明確區別，選取後提供原始圖片像素。最多回傳 64 個區塊，截斷與無有效座標均明確記錄；偵測結果不代表完整性或文字正確率。每頁最多查詢一次，計入時間與主控呼叫預算，另保留後續修復及驗證額度，不消耗修復嘗試次數、不發布候選。
- resolve_source：以文字檢索最多三個候選來源頁，模型定位後另一次來源驗證。可處理未對應或疑似對應錯誤的文字／表格。圖片的 caption 不足以證明圖片位置，此情況改由頁面恢復工具處理。定位成功只更新來源關聯，不等於內容驗收。
- read_regions：可選最多三個已查詢 region_ids 加入局部放大圖，仍須完整覆蓋全頁。程式優先以 PDF 完整表格列切分，可靠匹配時附上 Word 原生儲存格 ID 與文字；合併儲存格不切開，有表格時不採左右象限。模型只輸出 owned_rows／核心所屬內容，表頭、單位及擴展範圍只作上下文。needs_context 與 unreadable 分開處理：每區最多擴展一次，每次工具最多兩次擴展，共用原有預算。完成結果按來源像素、模型與契約快取；表格按來源列 ID 與欄位組裝成同一個結構化表格，再產生文本。原生儲存格缺漏及跨區重複會拒收，仍須核對原圖和實際文件／chunks。
- reparse_pdf：使用已轉換的原 Word PDF 或原 PDF，抽取指定實體頁，在隔離目錄重新呼叫 MinerU。即使原生 Word 沒報錯，也能因內容缺漏選用。解析成功不直接採用，必須經候選驗證。取消或逾時會終止解析器程序群組。
- rebuild_delivery：依原圖提出限定區塊的文字修正或重複移除。移除必須引用仍保留且文字相同的區塊；不能同時修改保留者，也不能僅憑單頁證據改寫跨頁區塊。重新產生文件與 chunks 後再核對。

模型可在工具失敗後改選其他方法，受每個問題及整份文件上限約束。相同工具、參數、來源與內容不得原樣重跑。完整文件、來源圖及 IR 存在程式端；主控摘要與局部請求有大小限制，不把整本文件放進單次提示。

### 候選、驗證與恢復

每次操作先保存 before_ir，再建立隔離候選。Package／Chunk 重建停用額外 VLM 修復，所有恢復階段模型呼叫走共用記帳。先檢查實際文件與 chunks 的文字覆蓋，再把候選交付與原圖逐頁核對。只有通過的候選可在 apply 模式採用；shadow 僅保存候選。

密集頁可拆成四個連續橫向區域核對，另外核對跨區閱讀順序；缺任一區域、版面證據不足或預算耗盡均不能通過。最終驗收檢查區域覆蓋及來源圖片 hash。

採用前保存具 hash 的 IR 快照與處理紀錄，再重建工作版本；中斷可重播快照。重建失敗會停止工作，不能發布半完成版本。原始 Word/PDF 與舊發布版本不變，候選、原版本 IR、驗證證據納入新版發布清單。

局部表格／圖片修復的採用狀態與整頁品質狀態分開。整頁仍待確認時，已通過的局部語意表示不會因此退回 [Image] 等佔位符。

### 預算與輸出

沿用 max_model_calls／max_seconds 作為審查、原有局部修復與新工具的總上限。新增 recovery_enabled=true、max_recovery_actions=6、max_recovery_attempts_per_issue=3；recovery_reserve_calls／recovery_reserve_seconds 保留設定相容性；新版 coverage-first 排程不在基本逐頁審查前扣留修復額度。工具執行仍須容納候選與最終核對的估計成本，且受剩餘總 deadline 約束。原有局部修復 max_actions 與新工具動作數分開記錄，模型呼叫及時間總上限仍共用。

outputs/recovery_report.json 記錄每個問題、工具、參數、結果與停止原因，可由批次下載的 recovery_report 類型取得。狀態區分 resolved、located_pending_review、applied_pending_review、rejected（步驟）、deferred、no_progress、attempt_limit、budget_exhausted、interrupted 等。前端顯示已採用結果、仍待處理與額度不足的數量；採用數不等於整篇通過數。

本版仍是有界工具控制：單次 PDF 重解析／頁面替換以一個實體頁為限，已知跨頁共用區塊不會用單頁內容覆蓋；來源模糊、難以讀取的文字、上下文／次數上限及驗證不通過會明確保留待確認。模型一致判斷不是人工正確率，仍需原圖抽查與保留測試集。

## 無人工介入的自動交付（2026-09-18）

新工作預設在額度內完成辨識、來源核對與可用內容匯出。未解決問題會產生 terminal 的 complete、partial 或 unverified 狀態；requires_human_review=false，不建立人工待辦、不在背景無限重試。執行完成與內容完整仍是不同概念；舊 quality_status / auto_rag_ready 保留整份文件的嚴格判定。

新增 read_source 工具：從目標 PDF 實體頁取出原生文字與實際繪出的嵌入圖片；不使用 PDF resources 中未出現在該頁的圖片。Word 原始 media 只有在像素完全相同時才能取代對應圖片。不依 caption 猜圖片歸屬。不用縮圖截斷簡報面板，也能讀到在轉換頁面上被其他圖片遮住的原始圖內容。每次模型呼叫最多三份材料，加一張全頁上下文；每項材料的來源 ID 必須完整、唯一、按順序回傳。原始圖片與來源清單保存於 agentic/evidence。

read_source 可宣告無法完整辨讀的材料，程式會以「無法可靠辨識」標記取代該項候選文字，保留來源與理由；模型推測的文字不會混入正式內容。有缺漏的候選仍需獨立核對：所有可讀區塊均正確且上下文完整、順序正確，並確認未覆蓋內容僅限已宣告的缺漏。只要另有無法解釋的遺漏，整個候選不採用。圖片摘要與原文轉錄分開標記；不能用圖片摘要跳過難讀的實質文字。

同一問題的同一工具及模型不能靠更換切法重複消耗嘗試額度。若模型重複提出失敗方法，控制器改選未嘗試的原始材料閱讀、PDF OCR 或分區閱讀。當既有 vlm 與 review_vlm 確實配置為不同端點或模型時，可選擇 review 模型辨讀；不建立額外服務、不自行把文件送到新的端點。所有工具及模型繼續共用原有次數、時間預算。分區圖從來源 PDF 重新渲染，最長邊最多 2400 像素，最多 4 倍座標倍率。

交付分為以下檔案：

- documents/*、chunks.jsonl：保留原解析與已採用修復的完整產物，用於追溯及來源比對，不應直接當作自動 RAG 白名單。
- delivery.md：供閱讀的自動交付版本；只保留可確認內容，未確認區塊及整頁缺漏會留下明確標記。
- rag_chunks.jsonl、rag_verified.md：只含可自動使用的來源核對內容。
- processing_report.json：完成狀態、可用區塊、缺漏、來源頁碼及原圖證據、RAG 排除原因。

區塊通過需要實際文件及 chunks 覆蓋、來源對應及證據雜湊有效。部分頁面的區塊還需要模型明確確認 context_complete；頁面閱讀順序不正確時不匯出。依賴的標題、表頭、註解或跨頁部分未確認，會遞迴排除相關內容。可用區塊重新切分時不跨越缺漏，且每個 chunk 必須帶齊已核對的依賴文字。合併依賴後超過 chunk 上限時，先拆回各區塊與其完整依賴，避免相鄰大段落排除獨立的小表格。具有明確表頭、完整矩形且無合併格或註解依賴的表格，可依完整資料列分塊，每塊重複已核對的表頭及外部依賴，記錄 table_source_rows，且所有來源列都必須能完整匯出。其餘超限內容仍記錄 complete_context_exceeds_chunk_limit，不任意截斷；內容仍可出現在 delivery.md。

保留 auto_rag_ready 作為整份文件可用的判斷，新增 partial_rag_ready / automatic_delivery.rag_ready 表示安全子集可用。原有來源轉換警告的明確禁止狀態仍優先。原始文字尚未核對、審查關閉、預算不足、來源證據失效，均不會自動進入此子集。

API GET /runs/{run_id}/rag-chunks 是自動 RAG 匯入入口；GET /runs/{run_id}/output?view=rag 只回傳核對後 Markdown，沒有合格匯出時不回退舊 rag.md。view=delivery 取得閱讀版，GET /runs/{run_id}/processing-report 取得缺漏紀錄。批次下載支援 rag_chunks、delivery、processing_report。匯出前核對發布 manifest、原始交付摘要及證據，失效或舊工作未產生新匯出時回應 409。畫面提供這三種下載並顯示部分完成狀態。既有完成工作不自動重跑或變更。

原生 PDF 文字直接保留，不讓模型改寫；圖片材料另做一次不提供候選文字的獨立辨讀，使用既有 review_vlm 並改變圖片順序、移除全頁文字上下文。逐字內容以忽略排版及標點後的文字和數字集合比對；任何不一致即標為缺漏，再進行交付驗證。這是在實際測試發現「整頁模型核對仍接受小字誤讀」後補上的防線，模型一致仍不代表人工正確率。新工作的時間與呼叫額度已改為下方自適應預算，舊工作明確保存的上限仍然有效。


## 工具排程與耗時紀錄（2026-09-18.6）

新工作 agentic.adaptive_budget=true。max_model_calls=120、max_seconds=7200 是硬上限，實際有效額度取以下值與硬上限的較小者：

- 預留動作數 A：啟用 recovery 時取來源頁數與 max_recovery_actions 的較小值，否則為 0。
- 呼叫：max(24, 來源實體頁數 × 2 + max(12, A × 7))。
- 時間：max(900 秒, 來源實體頁數 × 75 秒 + max(600 秒, A × 450 秒))。

7 次與 450 秒來自 read_regions 完整工具成本加一次規劃的基準值；工具執行仍依當時的實際耗時與共享剩餘額度決定是否可負擔。

1 頁文件為最多 24 次／15 分鐘，預設最多六次修復動作時，27 頁為 96 次／4,725 秒，47 頁為 120 次／6,225 秒（103.75 分鐘）；完成即結束。adaptive_budget=false 可使用固定的明確上限。既有或新工作的較小 max_seconds／max_model_calls 不會被自動提高。這個額度只涵蓋 Agent，Parse／Enrich 等既有階段成本另外記錄。

先完成可負擔的第一輪來源審查，再集中修復；問題依既有視覺風險排序，缺少月份關係的時程表優先於一般版面問題。具實體位置的密集頁可在首輪分區核對，避免直到修復額度耗盡才發現缺漏。模型選擇看到問題、來源的表格／圖片數、已嘗試方法和各工具完整成本；不再為工具選擇額外送入全頁大圖，規劃呼叫預設最多 120 秒，會依實際規劃耗時估計調整；規劃輸出上限 384 tokens、原因限一句話。逾時紀錄也會納入耗時估計，避免把曾逾時的模型當成快速模型。

工具預估包含候選辨讀、必要的獨立辨讀、候選交付核對和正式重建後核對，並以近期同類呼叫實際耗時修正保守估計。四張嵌入圖的 read_source 需要兩批、共四次辨讀加兩次交付核對；每次辨讀另預留一次格式修正，完整保守預留為十次呼叫，未使用的預留不計入實際用量。時間或次數不足時在模型讀取前停止該工具，保留明確原因，不依靠失敗後才回滾。估計不能保證每次模型延遲；執行仍有實際 deadline，失敗不採用未驗證內容。

同一問題同一工具／模型的失敗不因換裁切重試；表單混合文字與圖片時，規劃指引優先考慮分區讀取以保留欄位關係。舊表格修復不再位於預設工具控制器前面，因此不會先浪費兩次相同的表頭規則失敗。

目標頁保持原核對解析度；已映射的跨頁區塊保持完整相鄰頁解析度。一般鄰頁僅供版面上下文，使用最多 480×680 的概覽，文字邊界仍提供；不清楚的上下文不得猜測通過。每份交付的段落／chunks 索引可依交付雜湊重用，內容變更會重新載入。

review_coverage.json、agentic_report.json 及工作階段 stats 提供 budget 和按工具分類的 timing。review_state.json 每次呼叫記錄 phase、duration_seconds、timeout_seconds、image_count、payload_chars、tokens 和錯誤；recovery_report.json 記錄 estimated_cost 和工具實際 duration_seconds。方便區分規劃、辨讀、驗證和失敗重試，不能把 timeout 的空字串誤當作無原因失敗。

續跑只更新已完成階段的 checkpoint 標記，保留原 started_at／finished_at；重新執行失敗階段時會清除上一輪 finished_at／error，避免把停機等待算進前段耗時或顯示負值。API 階段 duration 是該階段最近一次執行區間，不是跨重試累計；Agent usage/timing 保留所有已記帳呼叫，包含已取消呼叫，適合分析跨續跑的實際模型成本。僅調整規劃等待時間／輸出大小時，以獨立 scheduler_version 記錄，保留有效的來源驗證 fingerprint 與已花費額度。

整頁核對只要求 target 的 required_block_ids 完整、唯一，且回覆不能出現未提供的 ID。若模型額外回報本次已提供的 context_blocks，程式保留 target 的核對結果、丟棄額外上下文觀察，不把鄰頁當成已核對，也不因此重寫內容。缺少 target、重複 ID 或捏造 ID 仍拒絕。只有完整的有效審查結果可快取；模型格式／ID 失敗在剩餘額度內可重新核對，不把失敗永久快取成內容問題。

模型審查格式或 ID 契約錯誤與內容缺漏分開處理：前者不啟動整頁辨讀／重寫工具，在最後核對且仍有額度時重試審查。持續失敗仍不通過，沒有「重試後直接相信」的例外。

交付節錄在 Markdown 標題處重新分段，避免前面頁面增加數行就使整份文件的每 16 行節錄都錯位。來源核對另外保存 scoped_fingerprint：所有文字、必要／上下文區塊、來源影像 hash、文件內順序與是否相鄰、chunks 的內容與區塊歸屬均參與比對；僅忽略無關的全域段落／chunk 編號偏移及目標區塊閱讀序號的共同位移。這不是只比對 IR。證據等價才能重用，變動仍需核對。重用時保留最初 reviewed_delivery_sha256 與 raw fingerprint，另記 reuse_reason；目前交付 hash 仍須匹配發布檔案。

## Word 頁碼定位與表格圖片（2026-09-21）

原生 Word 仍標為 logical；來源審查另外建立實體 PDF 頁碼關聯，不把邏輯頁 0 改稱實體頁 1。重複標題或短文字先列出來源候選頁，再以相鄰、獨立匹配的文字／表格錨點限制範圍；只剩一個候選才定位。推定的頁碼不繼續當成下一段的錨點。錨點矛盾、多個候選或原文未匹配時保留未定位。

Word 圖片以原始 relationship part 與 SHA-256 綁定，再比對 PDF 實際繪出的圖片。完全相同像素可定位；Office 重取樣／壓縮時，另以比例、64 與 256 像素的 RGB 誤差及競爭候選差距提出保守候選。相似度定位只決定要核對哪頁，不代表文字正確；重複圖片仍要利用父表格或相鄰錨點消歧。caption、附近的品牌名稱不能當作圖片定位證據。比對方法、候選頁、錨點及位置存於 evidence 下的 word-page-mapping.json。

表格圖片依實際 XML 儲存格取出，涵蓋合併格、重複出現的同一圖片、只有圖片的表格及巢狀表格。每張圖保留父表格 block ID、零起算的列欄與巢狀 cell_path、列標籤及來源圖片雜湊；圖片本體進入既有 Enrich／Package／Chunk。產出的「第幾列、第幾欄」說明是來源位置，不是圖中文字，也不能因此跳過圖片辨讀。同一段落中的浮動圖片只在定位參照一致、位置可比較時依視覺列與左右順序排列；其他情況保留 XML 順序。

Word 原圖以原始解析度、無損 PNG 保存，逐頁核對時額外附上。實測仍發現模型會沿用錯誤描述，因此增加不提供 caption、鄰近文字或既有描述的獨立原圖辨讀，每次至多四張。來源文字與交付不一致、辨讀不完整或回傳空內容，即使整頁模型聲稱 verified，該圖仍不通過。此防線只能拒絕矛盾，不能把另一個模型讀法直接當正解。圖片辨讀結果依原圖 hash、核對模型設定與版本快取，修復候選與正式重建共用；增加的呼叫計入原有預算，保留圖片的修復工具成本估計也包含這層核對。候選驗證必須攜帶相同原圖證據。

本機 backend/workspace/validation/word-structure-20260921/ 保存晴諾米 47 頁的解析／定位重播及第 2 頁的真實模型測試。這是結構與局部品質驗證，沒有宣稱整份 47 頁都通過新版語意核對。舊工作不自動重跑；解析與處理版本已更新，新工作不沿用舊表格圖片快取。


## 小圖格式修正與局部交付（2026-09-21.3）

來源辨讀的格式錯誤與無法辨識分開記錄。`complete=true` 卻沒有文字／場景內容、錯誤或缺漏的 source ID、JSON/schema 錯誤，只允許一次同來源的格式修正；最多兩次呼叫，跨續跑也不重置。只有有效回覆可快取，格式錯誤不當作來源不可讀，也不因此啟動整頁改寫。逾時與預算不足仍使用原有的錯誤／停止狀態。

新增 `repair_image` 工具及對應策略 SKILL，限定一張已定位的圖片。Word 使用嵌入原圖；具有實體頁座標的圖片使用來源 PDF 裁切。caption 不作為定位或讀字依據。Agent 看到具體失敗分類、可用工具與剩餘預算，圖片問題可先選擇可用的 OCR 取證，再選擇圖片修復或停止；不同模型角色只有配置確實不同時才可選，不把同一模型不同名稱視為新方法。

兩次不提供既有 caption 的讀取，分別輸出圖片類型、場景觀察、圖中文字座標及可辨讀狀態。文字須在相同區域一致才可成為候選，候選還要對原圖及實際交付文件／chunks 核對。若先前獨立讀字出現不同結果，後兩次一致不能抹去衝突；新版會將各次讀值與可用 OCR 列為來源觀察，對照原圖及有來源座標的放大裁切裁決。舊讀值也可能錯誤，不作為必須照抄的答案。未能裁決仍保留缺漏。模型一致是候選條件，不是正確率保證。

照片的場景與文字分成獨立區塊；不依賴未辨讀文字的場景可保留，猜測的招牌文字不進入該次採用結果的 facts／keywords。Logo、圖表、流程圖等文字相依內容建立程式端依賴關係，即使後續模型忘記回報依賴，只要必要文字未通過，自動閱讀版與 RAG 仍一起排除。無內容可保留時產生一個全圖缺漏標記，保留來源頁碼、原圖與雜湊。

候選驗證僅取得目標圖片在實際文件與 chunks 的對應字串，不混入同段落／同 chunk 的鄰圖描述。採用時檢查其他區塊內容及順序未改動；整頁品質與局部修復狀態分開。最終核對仍可否決候選，只有最後來源核對通過的內容能进入 `delivery.md`／`rag_chunks.jsonl`。原始 `documents/*`、`chunks.jsonl` 留供追溯，不應直接用於自動 RAG。

圖片工具保守預留七次呼叫：兩次讀取、最多兩次格式修正、候選核對、一次縮減候選後核對與正式重建後核對。局部驗證若發現某些描述無法確認、但其他內容可獨立成立，程式僅一次將未通過部分轉為缺漏，重建實際文件／chunks 並重新核對；仍未通過便停止，不重新猜測原圖。讀取與錯誤紀錄跨候選／續跑重用；同一策略不得原样重跑。已核對且僅剩明確缺漏時正常結束，不再用整頁改寫追逐同一個缺字；另有新問題仍可在既有預算內處理。

本版沒有安裝 PaddleOCR，也沒有宣稱 OCR 能解出這些小圖。後續整合須提供有界的讀圖工具，回傳文字、座標、辨識分數、來源雜湊及執行狀態，並針對這台 ARM64 主機驗證依賴、四張原圖品質與耗時，再決定是否加入工具清單。


## 共用驗收規則與快取預算（2026-09-21.4）

`review_policy.py` 統一三項判斷：

- `partial_review_accepted`：只有已宣告缺漏、完整且唯一的區塊集合、正確順序，以及其餘內容皆 verified 且 context_complete，才能接受部分交付。圖片候選、整頁候選、是否結束修復共用此判斷。修正了舊停止判斷沒有檢查 context_complete、漏回區塊仍可能視為完成的差異。
- `reviewed_block_usable`：整頁通過或局部內容明確具完整上下文；審查報告與自動 RAG 匯出共用，不再分別維護相同條件。
- `dependency_closed_subset`：移除缺少必要文字／標題／單位的區塊及其相依內容；圖片候選縮減與 RAG 匯出共用。
